# Occupation Summations, Japan & Korea 1945–1948

A static research guide to two monthly U.S. Occupation report series:

- **Summation of Non-Military Activities in Japan** (GHQ/SCAP), Nos. 1–35, September 1945 – August 1948. Nos. 1–5 also cover southern Korea.
- **Summation of United States Army Military Government Activities in Korea** (Nos. 6–21), continued as **South Korean Interim Government Activities** (Nos. 22–34), March 1946 – August 1948.

The cover page is a month-by-month table of contents of both series. Each report has a summary and its own table of contents, with every section linked to the page images on the Internet Archive. All 12,104 OCR pages can be searched in the browser.

The design follows [japan-internal-affairs](https://github.com/kmlawson/japan-internal-affairs) (see its `spec.md`), simplified for a small collection: no Spotlight, Sets or session marks.

## Files

| Path | What it is |
|---|---|
| `index.html` | The whole app: CSS, HTML shell and JS, with hash routing |
| `data.js` | `window.CATALOG`, one record per PDF (generated by `build_data.py`) |
| `files.json` | ID, archive.org item, title, PDF and OCR path per PDF (generated) |
| `catalog/<id>.json` | Catalogue output per report: summary, highlights, keywords, sections with PDF page ranges |
| `briefs/` | Cataloguing prompt, JSON schema, `run1.sh` (one report via `agy -p`) and `check.py` (validates and saves the output) |
| `fulltext-build/` | `prepare.py` (OCR pages → `records.jsonl`) and `build.mjs` (Pagefind index → `pagefind/`) |
| `pagefind/` | Full-text index (generated) |

The PDFs, the OCR text (Mistral OCR `mistral-ocr-4-1`, `ocr/*.md` with `<!-- page N -->` markers) and the Internet Archive upload lists live outside the repo, in the two collection folders.

## Record shape (`data.js`)

```
{ id, ia,          // short ID (J-16, J-04-phw, K-12-v2) and archive.org item
  s, no, d, d2,    // series (J/K), issue number, month YYYY-MM, end month for two-month issues
  t, v, pg,        // title, variant (second copy, section), PDF pages
  o, h, k, by,     // summary, highlights, keywords, model
  toc: [{ t, lv, p:[start,end], pp, s }],   // sections: title, level, PDF pages, printed page, summary
  sk: 1 }          // present only while a report is not yet catalogued
```

## Rebuild

```
python3 build_data.py
cd fulltext-build && npm ci && python3 prepare.py && node build.mjs
```

Cataloguing one report: `briefs/run1.sh <id>` (Gemini via Antigravity first, Claude Sonnet when Gemini is out of quota). Outputs are checked for page coverage by `briefs/check.py`.

Page numbers throughout are PDF page numbers, which is what archive.org's `/page/n<N-1>` links use; the reports' printed page numbers are recorded separately where the model found them.
